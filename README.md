# HRSCAN-UPDATE

ส่งข้อมูลสแกนลายนิ้วมือจากเครื่อง ZKTeco ขึ้น Supabase — ทำงานเป็น Windows service ประจำสาขา ไม่มีหน้าจอ ใช้งานผ่านเมนู CMD

```
เครื่องสแกน ZKTeco ──TCP 4370──▶ HRSCAN-UPDATE ──▶ Supabase ──▶ ระบบ HR
     ที่สาขา                    (service ที่สาขา)              (ดึงไปเองอัตโนมัติ)
```

สาขาที่ลง **ZKBioTime** ไว้ต่อเครื่องสแกนตรง ๆ ไม่ได้ เพราะโปรแกรมนั้นยึดการเชื่อมต่อไว้ตลอด
สาขาแบบนี้ให้ตั้งแหล่งข้อมูลเป็น `biotime` แล้วโปรแกรมจะอ่านจากฐานของ ZKBioTime ในเครื่องแทน

```
เครื่องสแกน ──▶ ZKBioTime (PostgreSQL ในเครื่อง) ──▶ HRSCAN-UPDATE ──▶ Supabase ──▶ ระบบ HR
```

ส่วนที่เหลือทำงานเหมือนกันทุกอย่าง — ตัวจำ (cursor), การกันข้อมูลซ้ำ และการส่งขึ้น Supabase ใช้ชุดเดียวกัน

## ติดตั้งที่สาขา

เปิด **CMD** ที่เครื่องของสาขาแล้ววางคำสั่งนี้

```
powershell -c "irm https://raw.githubusercontent.com/azsx69/HRSCAN-UPDATE/main/install/get.ps1 | iex"
```

สคริปต์จะติดตั้ง Git กับ Node.js ให้ถ้ายังไม่มี แล้วดาวน์โหลดโปรแกรมไปที่ `C:\HRSCAN-UPDATE` จากนั้นถามค่าตั้งค่าทีละข้อ

| ถามอะไร | ตัวอย่าง | หมายเหตุ |
|---|---|---|
| Branch code | `Store 1` | ต้องตรงกับที่ระบบ HR ใช้ ไม่งั้นข้อมูลจะไปโผล่ผิดสาขา |
| Machine code | `FP-01` | ไว้ไล่ที่มาของข้อมูลตอนมีปัญหา |
| แหล่งข้อมูล | `1` เครื่องสแกน / `2` ZKBioTime | เลือก `2` เฉพาะสาขาที่ลง ZKBioTime ไว้ในเครื่องนี้ |
| IP เครื่องสแกน | `192.168.88.175` | ถามเมื่อเลือกแหล่งข้อมูลเป็นเครื่องสแกน — ต้องอยู่วง LAN เดียวกับเครื่องที่ติดตั้ง |
| พาธ psql.exe / ชื่อฐาน | `C:\ZKBioTime\pgsql\bin\psql.exe` · `biotime` | ถามเมื่อเลือก ZKBioTime — ปกติกด Enter ใช้ค่าเดิมได้เลย |
| Supabase URL / service key | | ขอจากผู้ดูแลระบบ |
| ความถี่ sync | `5` นาที | |
| เริ่มดึงข้อมูลตั้งแต่ | `2026-01-01` | ข้อมูลที่สแกนก่อนวันนี้จะไม่ถูกส่ง |

ตั้งค่าเสร็จจะทดสอบการเชื่อมต่อให้ทันที แล้วติดตั้ง service ต่อ **ขั้นตอนติดตั้ง service ต้องใช้สิทธิ์ Administrator**

## ใช้งานประจำวัน

เปิด `C:\HRSCAN-UPDATE\install\menu.bat` — ไฟล์เดียวจบ

```
   1. ดูสถานะ + log ล่าสุด            5. สั่ง sync เดี๋ยวนี้
   2. ดู log วันนี้ทั้งไฟล์             6. แก้ไขการตั้งค่า
   3. เปิดโฟลเดอร์ log                7. Start / Stop / Restart service
   4. ทดสอบการเชื่อมต่อ                8. อัปเดตเป็นเวอร์ชันล่าสุด
```

ปกติไม่ต้องทำอะไร service ส่งข้อมูลเองทุก 5 นาที เปิดเมนูเมื่ออยากตรวจว่ายังทำงานปกติ หรือเมื่อสงสัยว่าข้อมูลไม่ขึ้น

## เวลามีปัญหา

| อาการ | ตรวจอะไร |
|---|---|
| ข้อมูลไม่ขึ้นเลย | เมนูข้อ 4 ทดสอบการเชื่อมต่อ — จะบอกว่าเป็นที่แหล่งข้อมูลหรือ Supabase |
| สาขาที่ใช้ ZKBioTime แล้วต่อไม่ได้ | ตรวจว่าบริการของ ZKBioTime เปิดอยู่ และพาธ `psql.exe` ในการตั้งค่าถูกต้อง |
| ชื่อพนักงานเป็นตัวประหลาด | เมนูข้อ 4 จะแสดงตัวอย่างชื่อ ถ้าอ่านไม่ออกแปลว่า encoding เพี้ยน แจ้งผู้ดูแล |
| เวลาสแกนผิด | ตรวจเวลาที่ตัวเครื่องสแกนก่อน โปรแกรมส่งเวลาตามที่เครื่องบันทึกไว้ |
| service ไม่ขึ้น | ดู `logs\service.err.log` |

log ของโปรแกรมอยู่ที่ `logs\sync-YYYY-MM-DD.log` เก็บย้อนหลัง 30 วัน

## หลักการทำงาน

โปรแกรมจำเวลาสแกนของแถวล่าสุดที่ส่งสำเร็จไว้ใน `state.json` รอบถัดไปจึงส่งเฉพาะแถวที่ใหม่กว่านั้น

**ถ้าส่งไม่สำเร็จจะไม่ขยับตัวจำ** ข้อมูลจึงไม่หาย เพราะ log ยังอยู่ในเครื่องสแกนและรอบหน้าจะส่งซ้ำ ส่วนแถวที่ส่งซ้ำจะไม่กลายเป็นข้อมูลซ้ำ เพราะฝั่ง Supabase กันไว้ด้วย unique constraint ของ `(branch, employee_code, scan_date, scan_time)`

เวลาทั้งหมดเก็บเป็นเวลาไทย ไม่ใช่ UTC

## สำหรับผู้ดูแลระบบ

ออกเวอร์ชันใหม่จากเครื่อง dev

```
install\release.bat v0.2.0 "แก้อะไรไปบ้าง"
```

แล้วให้แต่ละสาขาเปิดเมนูเลือกข้อ 8 เพื่ออัปเดต หากเวอร์ชันใหม่มีปัญหา ข้อ 9 ย้อนกลับได้ และถ้า service ไม่ขึ้นหลังอัปเดต โปรแกรมจะย้อนเวอร์ชันเดิมให้เองอัตโนมัติ

`config.ini`, `.env` และ `state.json` ไม่ได้อยู่ใน git การอัปเดตจึงไม่แตะการตั้งค่าและตัวจำของแต่ละสาขา

### ข้อควรระวังเรื่องความปลอดภัย

repo นี้เป็น **public** — Supabase service key มีสิทธิ์ข้าม RLS ทั้งหมด **ห้ามใส่ลงในไฟล์ใดที่ commit ขึ้น git** ให้อยู่ใน `.env` เท่านั้น ซึ่ง `.gitignore` กันไว้แล้ว หากเผลอ commit key ขึ้นไป ให้ถือว่า key นั้นใช้ไม่ได้แล้วและต้องออกใหม่ทันที การลบ commit ทีหลังไม่ช่วย

### พัฒนาต่อ

```
npm test        # ทดสอบตรรกะแปลงเวลาไทย, cursor, retry, การแบ่ง batch
npm start       # รัน service แบบเห็นหน้าจอ
node src/cli.mjs status | test-source | test-supabase | sync-now
```

เอกสารออกแบบอยู่ในโปรเจกต์ HR ที่ `Docs/superpowers/specs/2026-07-27-hrscan-update-design.md`
